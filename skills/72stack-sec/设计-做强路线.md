# 72stack-sec 做强设计（乌鸦 · 2026-09-10）

> 目标：把「能挖」升级成「可复利」——每次命中/漏报都回灌进发现引擎，而不是再堆百科。
> 范围：本机 `~/.grok/skills/skill`（对内名 skill；对外仓库名 72stack-sec）。
> 红线不变：最小伤害、禁批量扫描/DoS/内网横向、禁破坏性写；本设计不加任何利用步骤。

---

## 1. 产品定位（一句话）

**语义审计发现引擎 + 三道门闩 + 双轨调度**，payload/知识模块只是「有靶子才确认」的弹药库。

实证锚点：`references/methodology/14-semantic-audit.md` —— ~90% findings 来自结构后的语义三问，payload 库直接命中≈0。

---

## 3. 架构（做强后）

```
任务开场
  → 威胁模型（业务/栈/面）写入 suspects 头
  → 结构提取（表单/接口/JS）
  → Phase 4.5 语义三问 → suspects.md（发现引擎）
  → 门闩：覆盖率硬闸 + gate_check + 危害定性
  → 仅对 S-xx 查表确认（知识库模块，显式指针）
  → format 落盘
  → 命中/漏报 → semantic-blindspots.md（回灌）
```

**立法优先级（冲突时）：** `~/.grok/rules` > `SKILL.md` > `知识库/` > `references/`（仅显式指针）。

## 5. 成功标准

- 新任务默认产出 `suspects.md`，covered 前能指出覆盖率是否过闸。
- 每确认 1 个洞或明确漏报 1 次，盲区库至少多 1 行。
- 主控开场不再通读 `references/methodology`。
- 两周内至少 1 次「盲区条目 → 短表/模块补强」的闭环（经 hunt-iter）。
