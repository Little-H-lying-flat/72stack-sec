# 多 Agent 执行工作流(设计稿 v0)

> 视角:目标面大到单会话串行打不完时,把 Phase 2/3/4 的**可并行段**分片给子 agent,主 agent 收敛。**默认关闭**——本文是设计稿,启用条件见 §1。约束(反幻觉 / scope / 证据纪律)在多 agent 下**只增不减**。

---

## 1. 激活策略(默认关)

**启用条件**(满足全部):
- 用户明确说"并行 / 多 agent / 分片打",或 Phase 3 资产矩阵 ≥15 个活资产且时间盒 <4h
- 项目规则**不禁自动化**(国内 SRC 普遍禁扫描器——禁则一律串行低频,见 compliance.md)

**停用条件**(任一即回退串行):
- 目标面 ≤5 资产(编排开销 > 收益)
- 任一 agent 触发 scope 越界 / 限速失控
- WAF 开始按 IP 段拦截(并行放大了指纹)

---

## 2. 角色表

子 agent = 全新上下文,**不继承主会话记忆**,任务卡必须自包含(§3)。

| 角色 | 数量 | 职责 | 禁止 |
|---|---|---|---|
| **C 协调者**(主 agent) | 1 | 拆任务卡 / 发预算 / 合并结果 / 差分确认 / 去重登记 / 唯一对外结论出口 | 自己下场打点(串行模式除外) |
| **R 侦察员** | 2–4 并行 | Phase 2 分源 OSINT:CT 日志 / Wayback / GitHub dorks / FOFA——各领一源 | 任何发往目标的数据包 |
| **E 枚举员** | 1–3 并行 | Phase 3 分片活资产探测 + 指纹,产出资产矩阵分片 | 带 payload 的探测(归 H) |
| **H 猎手** | ≤3 并行 | Phase 4 按 **1 个 playbook = 1 个 agent** 打点,返回原始 HTTP 证据 | 跨 playbook 混打;写操作;改 scope |
| **V 验证员** | 1 | 对 H 上交的候选 finding 跑三段差分确认(03-evidence-discipline §3 原则 2) | 采信 H 的自我结论 |

H 的数量上限 3 是**风控约束**不是资源约束:同源 IP 并行打点会放大指纹,即使规则允许自动化也要控并发。

### 2.1 Bypass-Miner 角色(20260831(单项分发模式))

| 角色 | 数量 | 职责 | 禁止 |
|---|---|---|---|
| **B 绕过矿工** | 1 | 专职处理 H 上交的"被拦/403/统一拦截页"信号:Read 02-bypass-toolkit→按过滤器画像构造绕过变体→返回原始对照证据 | 打新目标;下结论 |

- 触发:H 返回 BLOCKED 类结果的队列项 ≥3 或单项被拦探针 ≥5(满足即发 B 卡,单项分发模式=一次一个子代理)
- 与 H 的边界:H 遇拦即记 BLOCKED 跳走(§4.1 自愈);B 只做绕过重打,**不做发现**
- 卡片模板沿用 §3,【任务】段改为"Read references/methodology/02-bypass-toolkit.md 后,对 {ENDPOINT} 的 {BLOCKED_SIGNAL} 按其决策树构造绕过变体"

## 3. 任务卡(子 agent prompt 模板)

每个子 agent 的 prompt 必须逐字包含以下五段,缺一不发:

```markdown
【scope 硬边界】
in-scope: <逐条列,含通配符>;
out-of-scope: <逐条列>;
任何一刻发现要碰的资产不在上表 → 立即终止返回,不试探、不近似。

【任务】
<一句话,例:Read references/playbooks/sqli.md 后,按其参数频率表
对 {TARGET} 的 {ENDPOINT_LIST} 执行 SQLi 探测>

【payload 出处纪律】
payload 只准出自上述 playbook 文件;文件里没有的变体不要自己编。

【预算】
QPS ≤ {N};总请求 ≤ {M};超预算立即收尾返回。
禁止:写操作 / 删改数据 / 撞库 / 大流量。

【返回格式】
1. 结果状态: DONE / BUDGET_STOP / SCOPE_STOP / BLOCKED
2. 命中列表(如有): endpoint | 探针 | 原始请求+响应摘录(未加工)
3. 负面结果(测了什么没中): 同样要列——这是协调者去重与覆盖率的依据
```

要点:**H 只交原始证据,不下"漏洞"结论**——结论由 V 差分确认、C 登记后才成立,对应 SKILL.md 反幻觉硬约束 3。

## 4. 分阶段编排

### Phase 2 · Recon(天然并行,最安全)

```
C 按源拆 4 张 R 卡:CT 日志 / Wayback / GitHub dorks(带 org dork 清单) / FOFA
→ 各 R 返回资产条目(URL, 来源, 首见时间)
→ C 合并去重 → 资产清单(来源 ≥3 的 MUST 输出不变)
```

### Phase 3 · Enum(按资产分片)

```
C 把资产清单切片(每片 ≤10 域),发 E 卡(附探活+指纹规范)
→ 各 E 返回 资产矩阵分片(域→端口→服务→指纹→JS endpoint)
→ C 合并 → 触发 SKILL.md Phase 3 条件 Read(指纹命中云/银行/电信同理)
```

### Phase 4 · Hunt(按 playbook 分片,门闩最严)

```
C 依资产矩阵信号选 ≤3 个 playbook → 每个发 1 张 H 卡(playbook 路径写死在卡里)
→ H 返回原始命中证据 + 负面结果
→ V 逐条跑三段差分(baseline→attack→对照),不成立的降级"待验证假设"
→ C 查去重登记簿(§5)后登记 finding → 全部预算用尽或命中收敛 → 回串行
```

**同一 endpoint 不允许两张 H 卡同时打**(先到先得,后到的卡改派)——避免并发探测互相污染基线。

### Phase 5 · Report(永远单点)

C 独自汇总,Read compliance.md + templates 走原流程。子 agent 不参与报告。

---

## 5. 全局治理(C 维护三本账)

> 三本账的单人落地格式(scope.md / findings.md 台账)见 [`09-target-workspace.md`](09-target-workspace.md);并发模式在同名文件上升级为卡粒度。

| 账 | 内容 | 用途 |
|---|---|---|
| **scope 账** | in/out 清单 + 每张卡的派发记录 | 任何越界可追溯到卡 |
| **去重登记簿** | `endpoint × 漏洞类` 二元组,登记后不再派卡 | 落实去重抑制;H 之间、跨轮次都不重复打 |
| **预算账** | 每卡 QPS/请求数 + 全局已耗 | 全局 ≤ 串行基线的 3 倍;防"并行变压测" |

**全局预算铁律**:并行模式全周期发包总量 ≤ 单 agent 串行模式预期量的 3 倍。超了立即冻结新卡。

---

## 6. 失败与回退

- 子 agent 返回 SCOPE_STOP / BLOCKED → C 记账换卡,不重试同一目标
- 子 agent 超时 / 结果格式不合规 → 该分片由 C 串行接管,不重发(避免重复发包)
- 任何 agent 的输出**没有原始 HTTP 证据** → 整卡作废,按未测处理
- 两张卡对同一 endpoint 结论矛盾 → 以 V 差分复核为准,H 结论一律不作数

---

## 7. 何时不该用多 agent

- 国内禁扫描器的 SRC(大多数)——并行本身就是风险信号
- 需要登录态的纵深测试(会话状态跨 agent 不可共享,见 enterprise-src-hunt 的双账号隔离)
- 时间盒充裕的单目标(串行的差分质量天然更高)
- C 自己没打过该 playbook 类型的场景——先串行走通一遍再并行
