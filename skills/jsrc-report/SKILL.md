# JSRC-REPORT

把一个已验证的漏洞写成 JSRC 提交级 docx 报告。输入是漏洞信息（平台、请求/响应包、
实测结果），输出是 `D:\SRC\京东\<报告名>.docx` + 生成它的 `gen_report_vN.py`。

```
漏洞信息 → 补齐关键事实 → 定级判断（合并/拆分） → 写 gen_report_vN.py
        → 运行生成 docx → 自检清单 → 交付
```

---

## 一、硬性格式规范（不可更改）

参考文档：`D:\SRC\京东\京东售后服务单敏感信息批量泄露.docx`。
所有报告 = **纯 Normal 段落、宋体、无表格、无标题样式**。禁止使用 Heading/表格/封面。

### 生成脚本骨架（逐字使用，只填正文）

```python
# -*- coding: utf-8 -*-
"""生成vN报告：<一句话漏洞概述>"""
from docx import Document
from docx.shared import Pt, Cm, RGBColor
from docx.oxml.ns import qn
from docx.oxml import OxmlElement

doc = Document()

def set_font(run, name=u'宋体', size=None, bold=None, color=None):
    run.font.name = name
    rpr = run._element.get_or_add_rPr()
    rf = rpr.find(qn('w:rFonts'))
    if rf is None:
        rf = OxmlElement('w:rFonts'); rpr.append(rf)
    rf.set(qn('w:eastAsia'), name)
    if size: run.font.size = Pt(size)
    if bold is not None: run.font.bold = bold
    if color: run.font.color.rgb = color

def para(text, bold=False):
    p = doc.add_paragraph()
    set_font(p.add_run(text), bold=bold)
    return p

def req(text):
    """请求/响应包：Consolas 10pt 深红"""
    p = doc.add_paragraph()
    set_font(p.add_run(text), name='Consolas', size=10, color=RGBColor(0x8B, 0x1A, 0x1A))
    return p

def shot(text):
    """截图占位：灰色加粗，提交前替换为实际截图"""
    p = doc.add_paragraph()
    set_font(p.add_run(u'【此处插入截图：' + text + u'】'),
             size=10, bold=True, color=RGBColor(0x80, 0x80, 0x80))
    return p

# ============ 正文 ============
# ...（按第二节结构填充）

out = r'D:\SRC\京东\<报告文件名>.docx'
doc.save(out)
print('saved:', out)
```

**注意**：正文含单引号（如 `var canEdit = 'false';`、`"entry":false`）时，
用变量拼接避免引号嵌套 SyntaxError：
```python
CE = "'false'"; CT = "'true'"
para(u'响应体中 var canEdit = ' + CE + u' 改为 ' + CT + u' ...')
```

### 正文结构（固定顺序）

| # | 段落 | 样式 | 写法 |
|---|------|------|------|
| 0 | 标题 | 14pt 加粗 | `【平台名】漏洞一句话：入口方式 + 可做什么 + 验证状态` |
| 1 | **漏洞类型** | 标签加粗 + 正文 | 如：未授权访问 / 越权（说明根因：仅前端隐藏、服务端无校验） |
| 2 | **危害类型** | 标签加粗 + 正文 | 具体危害面：资金损失 / 敏感信息泄露 / 数据篡改 |
| 3 | **漏洞危害描述** | 标签加粗 + 正文 | 编号列表 1.2.3.4.：入口→能力→已验证事实→量化的业务影响 |
| 4 | **复现步骤** | 标签加粗 + 正文 | 编号步骤，每步一个动作；关键 HTTP 包用 `req()`，**每步末尾跟一个 `shot()`** |
| 5 | **危害** | 标签加粗 + 10pt 正文 | 引用 JSRC V9.0 条款论证定级；量化上限/持续性；建议审计历史记录 |
| 6 | **修复建议** | 标签加粗 + 正文 | 1. 2. 3. 连续编号写在一段：服务端校验、排查同类、审批/风控/审计 |

规则：
- 标题外的首个正文段落即 `漏洞类型`，**不要**写「一、二、三」章节号，不要加封面。
- 每个 HTTP 请求写完整：方法 + 路径（含 query）+ `Host:` + 完整 body，放进 `req()`。
- 修改响应体的漏洞必须写明：原始字段值 → 修改后值 → 前端出现什么功能。
- 敏感字段（PIN/工单号/手机号）在包里用真实值，截图阶段才脱敏；但报告里不写密码/token。

## 二、诚实性矩阵（报告可信度的核心）

每个操作必须归入三类之一，混写=报告被挂起：

1. **已验证可行** → 写明操作对象（必须是自己账号/自己的测试数据）、结果。
2. **已验证被拦截** → 如实写「后端校验权限，操作失败」，附被拒截图。这反而是论据：
   用「防护不一致」论证——同平台其他接口漏配校验，证明校验是逐接口部署的。
3. **未测试（影响业务/红线）** → 写「请审核老师内部验证接口」，给出建议验证方式
   （普通账号构造同样请求即可复现）。绝不谎称已验证。

删除/发布/切换版本这类影响线上业务的写操作，默认走第 3 类；自己建的测试数据
（名称含【我是测试】）可以实测删除。

## 三、内容红线（写报告前自查，违规条款写进报告的合规声明）

来源：`D:\SRC\京东\JSRC测试违规红线速查.txt`、`jsrc_v9_text.txt`。

- 只用本人账号；可注册系统最多 2 个自己账号互测。
- 越权读真实数据 ≤5 组，截图脱敏，严禁批量/脚本拉取。
- 新增数据标题带【我是测试】。
- 资产类（京豆/返利/券）：只发本人账号、一次性最小金额、到账即停；报告主动写合规声明
  （本人账号 / 一次 / 最小金额 / 未触上限 / 未向他人发放）。
- 不做 DoS、不打内网、写注入不自动化、webshell 只 echo 验证。
- 报告只存本地 `D:\SRC\京东`，不存云盘云笔记；修复前不公开。

## 四、定级与合并拆分（JSRC V9.0）

定级基线：
- 登录态后台模块越权/前端权限位绕过 = **中危**基线（「绕过认证」≠越权，高危#2 要求
  核心系统 + 绕过认证直接访问管理后台或越权执行敏感操作）。
- 上浮高危论据：核心业务系统、真实资金/有价资产、可规模化、可持续（每日重复）。
- 中危#3 明确把「少量返利/京豆」列为经济影响较小——但当日上限达数百~数千元、
  可每日重复时，在【危害】段论证不适用该条，建议按实际资金影响上浮。
- 纯前端暴露、后端有校验（编辑点了没用）= 低危~中危，如实写。

合并拆分：
- 同一系统 + 同一根因（如同一未授权访问引发的多处越权）→ **合并 1 份**，报告内引用
  合并规则。
- 同一系统不同接口的水平越权 → 记前 3 个有效，超出的不重复刷。
- 不同系统 → 分开提交，文件名区分平台。

## 五、写作铁律（历史踩坑，违反=返工）

1. **抓包来源只写 Burp**，绝不写「F12 抓的/Network 面板」。唯一例外：漏洞技术本身就是
   DOM 编辑（删 disabled 属性），此时如实写 F12 Elements 操作。
2. **平台名必须准确**（如 Oxygen Skill 平台、全媒体统一客服平台、售后可视化平台），
   用用户告知的正式名称，不造缩写。
3. **数据一致性**：多个请求里的 ID（instanceId/服务单号/PIN）必须一致；用户纠正过的值
   全文统一替换。
4. 逐操作如实：可行/被拦截/未测 三态，绝不把「前端显示成功」写成「已实测生效」。
5. 报告被挂起要求补细节时：补充完整请求响应包、定位信息（requestId/traceId/尾号）、
   明确的验证路径。

## 六、工作流

1. **收集输入**：平台 URL、漏洞入口（URL拼接/响应改包/DOM/接口fuzz）、完整请求响应包、
   每个操作的实测结果。缺哪项问用户要哪项，不臆造请求体。
2. **定级与合并判断**（第四节），和用户确认合并/拆分。
3. **编号**：扫描 `D:\SRC\京东\gen_report_v*.py` 取最大 N+1，新脚本 `gen_report_vN.py`。
4. **写脚本**：骨架逐字复制，只填正文；引号嵌套用变量；保存后立即 `python` 运行。
5. **自检清单**（生成后逐项过）：
   - [ ] grep 脚本无「F12」字样（DOM 型漏洞除外）
   - [ ] 所有请求包 method/path/Host/body 完整，多包之间 ID 一致
   - [ ] 复现步骤每步都有对应 shot() 占位
   - [ ] 未测操作写的是「请审核老师内部验证」，没有谎称已验证
   - [ ] 资产类含合规声明；新增数据写了【我是测试】
   - [ ] 危害段引用了 V9.0 条款 + 量化影响
   - [ ] docx 段落数合理（25~35 段）、打开无格式错乱
6. **交付**：报告 docx 路径 + 一句话说明报告三态结论（哪些已验证/哪些留审核）。

历史命名参考：`京东售后可视化平台越权操作规则策略.docx`、
`京东UX平台京豆发放池未授权访问.docx` —— 模式：`京东<平台简称><漏洞行为>.docx`。
