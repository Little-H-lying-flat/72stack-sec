# 虚假漏洞过滤器

Phase 3 命中候选漏洞后，Phase 4 验证前先过这张表。命中任一"虚假"信号 → 降级或丢弃。

## API 越权类

| 候选信号 | 虚假条件 | 验证方法 |
|---|---|---|
| 接口看似无鉴权 | 全局拦截器自动注入 token，手动 curl 漏带 header | 从 DevTools Network 复制完整请求头重放 |
| ID 替换返回数据 | 返回空壳 `{code:0,data:{}}` 无真实数据 | 对比正常请求的响应字段完整性 |
| ID 替换返回 404 | 后端有归属校验，ID 改了就查不到 | 非漏洞，丢弃 |
| 返回脱敏数据 | 手机号 138****8888 | 降级为信息泄露低危 |
| 越权返回他人数据 | 数据是公开信息（如商品名称） | 非敏感数据，低危 |

## WebView 类

| 候选信号 | 虚假条件 | 验证方法 |
|---|---|---|
| web-view url 看似可控 | url 在 setData 前被白名单校验 | 追踪 setData 前的过滤函数 |
| 子域绕过 | 微信运行时二次校验 webviewDomain | 实际在小程序中打开看是否报错 |
| `@` 绕过 | 微信校验的是完整域名非前缀 | 实测报错 |
| file 协议 | 微信默认禁止 | 非漏洞 |
| javascript: 协议 | 微信过滤 | 非漏洞 |
| 加载外部页面但无 JSBridge | 不携带小程序鉴权 | 仅钓鱼，低危 |

## 信息泄露类

| 候选信号 | 虚假条件 | 验证方法 |
|---|---|---|
| Storage 有 token | 接口鉴权用 header 不用 Storage | Storage 泄露无直接危害 |
| 硬编码字符串像 AppSecret | 是测试值/已废弃 | 实际请求微信 API 验证 |
| 接口返回手机号 | 已脱敏 | 降级 |
| 云开发 env 公开 | 云函数有安全规则 | 实际调用看是否拒绝 |
| console.log 泄露 | 生产环境日志被禁用 | 非可利用 |

## 业务逻辑类

| 候选信号 | 虚假条件 | 验证方法 |
|---|---|---|
| 支付金额前端改了 | 后端调微信统一下单重新生成金额 | 看支付请求是否走微信支付 |
| 优惠卷无限领 | 后端用户维度幂等 | 并发实测看是否真的多次到账 |
| 订单状态前端改 | 后端按 DB 状态校验 | 实际下单看状态是否真的变 |
| 验证码爆破 | 速率限制拦截 | 测速率限制阈值 |
| 活动接口返回成功 | 空壳响应，资源未实际发放 | 查实际资源到账 |

## 通用验证原则

1. **必须有可观察结果**：数据返回 / 支付成功 / 页面加载 / 资源到账
2. **必须排除兜底逻辑**：很多接口对错误输入返回 `{code:0,data:{}}` 看似成功
3. **必须对比正常与异常**：正常请求的响应是基准，异常请求必须返回**有意义的差异**
4. **必须实际重放**：DevTools Network → Copy as curl → 改参数 → 实际发送
