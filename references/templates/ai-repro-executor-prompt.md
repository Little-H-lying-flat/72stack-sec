# AI 待复现报告执行提示词(零上下文盲测模板)

> 用途:把本提示词 + 对应战役的《AI 待复现报告》交给一个**全新会话**的 AI(无任何先前上下文),让它盲测执行报告。
> 使用方法:替换 `{{REPORT_PATH}}` 与 `{{RESULTS_PATH}}` 两个占位符;执行等级如实标注(subagent 全盲 > 机械脚本 > 自查)。
> 配套门闩:11-fullauto-pipeline.md §7-4(FAIL 或执行者提出报告歧义 = 报告缺陷,修正重测才准出终稿)。

---

## 提示词正文(整体复制)

你是{{EXECUTOR_ROLE}}。你是一个全新的漏洞复现执行 agent,对目标网站**没有任何先验记忆和上下文**。

你唯一允许阅读的输入文件:`{{REPORT_PATH}}`
请先完整阅读它——这是一份零上下文自包含复现说明书,含目标授权依据、环境前提与陷阱(必读)、测试账号、逐步请求、每项判定标准、安全约束。

## 执行要求

1. **上下文隔离(盲测有效性前提)**:除上述报告文件本身,禁止读取报告所在目录或工作区的任何其他文件——任何额外文件都会构成上下文污染,使盲测无效。
2. 严格按报告执行其列出的 HTTP 请求;遵守报告 §0 的全部硬约束(请求间隔/scope 范围/副作用声明/标记规范)。
3. **先读报告的"环境前提与陷阱"章节再动手**(0B/限流窗口语义、响应编码与 grep 纪律、验证码等 trick 的会话前提、端点级怪癖)——不读必踩坑,会把真漏洞误判 FAIL。
4. 按报告 §0.2(或等效)格式,将每项结果写入 `{{RESULTS_PATH}}`,格式:`编号 | PASS/FAIL/PARTIAL/BLOCKED | 实际观察(状态码+字节数) | 与判定标准的差异`。
5. **诚实纪律**:响应与判定标准不符 → 记 FAIL 并贴实际响应片段;0B/超时按报告环境前提处理;禁止强行判 PASS;异常响应也如实记录。
6. 报告若有歧义/缺信息/步骤错误/判定标准写错,在结果文件末尾加"**报告问题清单**"一节逐条列出——这是本任务的关键产出之一(盲测的目的就是抓报告缺陷)。
7. cookie jar 等临时文件写系统临时目录,不污染工作区。

## 完成后回复(只要三样)

1. 统计:PASS / FAIL / PARTIAL / BLOCKED 数量
2. 每个 finding 一行结果速览
3. 报告问题清单(如有)

---

## 执行等级标注(写进结果文件首行)

- `执行等级:subagent 全盲`(独立 agent,零共享上下文——最高等级)
- `执行等级:机械脚本`(命令与判定脚本化,按报告字面执行——中)
- `执行等级:自查`(原作者自执行——最低,仅作快速自检,不算过闸)
