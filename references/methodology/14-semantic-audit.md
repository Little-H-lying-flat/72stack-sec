# 攻击面语义审计——发现的主引擎

> 视角:四战役产出溯源(20260831)的结论——**~90% findings 来自结构提取后的"表单/参数语义审视",payload 库直接命中≈0**。payload 是确认弹药,不是发现引擎;发现引擎是**对每个字段/防线/跳转的语义级提问**。本文件定义这道工序:Phase 4.5,在原型路由(10 号)之后、payload 探测之前。

---



## 0. 威胁建模前置(20260831:先整体认知,再定向探测)

> 三问是逐元素微观审计;开打前先花 10 分钟建**宏观认知**——业务/技术栈/攻击面三件事,决定哪些面值得优先问。产出写 suspects.md 头部"威胁模型"节。

### 0.1 三件事

| 认知 | 问 | 产出 |
|---|---|---|
| **业务** | 这是什么业务的站?钱/数据/权限从哪进哪出? | 高价值流清单(登录/支付/上传/管理面) |
| **技术栈** | 服务端/前端/DB/框架/中间件?(指纹+报错+header) | 栈画像→映射 10 号原型路由 |
| **攻击面** | 入口在哪?哪些面暴露(登录/搜索/上传/API)?认证边界画在哪? | 攻击面地图(suspects 分优先级的依据) |

### 0.2 SPA/无权限场景触发器(先 JS 后探测)

页面空白/提示无权限,但源码仍有 JS 资源 → **JS 就是后门地图**,四步起步序列(逐字执行):

1. **打开页面**(浏览器渲染,记录重定向/空白/权限提示——它们本身就是认证边界情报)
2. **收集 JS**(源码+网络面板全部 JS 资产,含懒加载 chunk)
3. **理解业务**(从页面文案/路由名/接口路径还原业务流:钱/数据/权限在哪)
4. **提取接口**(js-recon 三模式抽端点 → 接口清单 = §5 接口三问的输入)

然后按 §5 接口三问打。前端打不开不等于没得打。(juice-shop 实证:bundle 42 端点全图即此路径;图 6-2 会话实录同款序列)

### 0.3 产出示例

```
## 威胁模型
- 业务:电商(商品/购物车/支付)——高价值流=登录/下单/支付
- 栈:IIS+ASP+Access(80) / Apache+PHP5.3+MySQL(9090),无 WAF
- 攻击面:注册登录(无验证码族)/支付回调/后台路径未知/上传未定位
- 优先级:认证后功能 > 支付流 > 注入面 > 信息泄露
```

## 1. 三问清单(对 Phase 3 采到的每个结构元素)

### 1.1 每个表单字段问:"服务端信吗?"

| 信号 | 语义可疑点 | 后续验证方向 |
|---|---|---|
| `type=hidden` 字段 | 客户端可控的敏感值(username/price/uid/redirect) | 篡改重发(5vshop F-11 Pay_cz username、F-24 total/allmoney/money1 同款) |
| 金额/数量/单价输入 | 服务端是否重算 | 改 0.01/负数/0(F-24 实证) |
| username/uid 出现在 body | 服务端从会话取还是从参数取 | 换他人用户名(F-11 跨用户建单) |
| id/pkid/pid 类参数 | 遍历越权 or intval | 换不存在值消费判别→换他人 id(BOLA) |
| verifycode/captcha 字段 | 服务端校验存在吗?session 码何时写入? | 空会话 trick(F-09 家族五口) |
| goto/redirect/url/return | 跳转白名单 | 换外域(注意:实测也可能不被消费,如 down.php) |
| 文件名/路径参数 | 服务端拼接? | 遍历序列(10-traversal-lfi) |
| **表单完整性**(隐藏 action/step 字段) | 缺字段时服务端行为? | 静默回显=mlecms act=register 实测陷阱 |
| 页面/JS 里的演示账号/默认口(demo/test/123456/占位 value) | **演示号当钥匙**——直接当登录凭据试 | 命中即未授权面(20260831) |

### 1.2 每个功能问:"这道防线真实存在吗?"

- **验证码**:字段存在≠校验存在(F-09 五口);session 码何时写入(图片请求/页面加载);失败提示是"不正确"还是"必填"(mlecms feedback 严 vs register 松——**同站可两套实现**)
- **审核门**:写入成功≠公开渲染(F-22 5vshop 有审核门 vs F-32 mlecms 无)——写入后必须回列表页看渲染
- **越权校验**:改 id/用户名/单号重发,看所有权校验(F-02/F-08)
- **失败锁定/限速**:同错误请求 5 连发看响应与延迟变化(F-17/F-25)
- **金额校验**:负数/0/非数字/超小额四发(F-34 对照)
- **回调验签**:无 sign POST 看是否静默丢弃(F-15)

### 1.3 每个跳转问:"这个跳转去哪?"

- `location=`/`Location:`/`meta refresh`/JS location 的目标来源(固定/参数化/base64)
- base64 形态先解码再判(mlecms recharge goto=L21sZWNt... 实测)
- 参数化跳转→外域测试;不被消费也记录(排除项亦是产出)


### 1.4 登录页规则(20260831)

打开是登录页 ≠ 换资产,标准动作:

1. **先找登录后面的东西**:业务 API(登录页引用的 JS/接口)、跳转后的业务 host(可以是本 host 网关)
2. **主业挖未登录**:登录墙外的业务面照常审计;登录表单"看得见的面"(可见参数/明文校验/验证码口)打通或证伪就停
3. **不耗**:繁琐验证码/别人的 SSO/同皮登录壳——不烧预算
4. 拿到会话(注册/演示号/合法凭据)→ 立即转 §1.1 认证后三问

## 2. 产出物:语义可疑点清单(suspects.md)

Phase 4.5 输出写入 `work/<slug>/suspects.md`,每行:

```
S-01 | guestbook.php.title | 无验证码字段+列表页直出? | 表单提取 | 待验证 | → XSS 存储面
S-02 | Pay_cz.username | hidden 字段,服务端信? | 表单提取 | 待验证 | → 越权建单
```

列:**编号 | 对象 | 语义疑问 | 证据来源 | 验证状态(待验证/confirmed/clean) | 映射 playbook 类**。

**这份清单才是 payload 探测的输入**:每个 S-xx 按"映射 playbook 类"去查表拿确认弹药——弹药有了靶子,不再按类盲扫。

## 3. 覆盖指标(发现引擎的硬指标)

- **表单覆盖率 100%**:Phase 3 采到的每个表单 × 每个字段,三问 1.1 过一遍——漏一个字段=漏一个 S-xx 候选
- **认证后面 100%**:登录后可达的每个页面,表单+链接+参数全提取进三问——**全部 High 都来自这里**(F-02/08/14/24/32 实证),它不是"结构提取的一部分",是独立引擎
- **防线清单 100%**:1.2 的六种防线,每个认证后功能至少过一遍对应问句
- 未达标的"测完"=假测完(三查门闩追加第 4 查:**suspects.md 覆盖率**)

## 4. 与既有工序的关系

| 工序 | 分工变化 |

## 5. 接口三问(API/SPA 型目标,20260831 增补)

> 表单三问依赖"页面表单可见"——SPA/API 型目标(JS bundle + REST 端点,无表单)需换用本节。Juice Shop 首战已实证的信号标注。

### 5.0 前置:结构来源不同

表单型:页面 HTML 表单。**接口型:js-recon 三模式**(11 §3-8:引号字符串+模板字符串+懒加载 chunk)从 bundle 抽端点(juice-shop 实测 42 端点),再 enum 分型(未认证 GET 探活:200 公开/401 认证/500 异常)。

### 5.1 三问(API 版)

| 问 | 信号(参数/响应语义) | 验证方向 | juice-shop 实证 |
|---|---|---|---|
| **①参数:服务端信吗?** | 客户端可控的 id/email/userId/quantity/price;响应回显的内部字段 | 改他人 id(BOLA)、改数量金额为负/0、 mass assignment(多塞字段) | /rest/basket(id)/ PUT /api/Quantitys |
| **②声明:鉴权真在吗?** | 响应体含本不该返回的字段(email/password hash/token);401 与 403 的区分度;同资源不同端点鉴权不一致 | 无 token 访问"认证"端点;对比同数据两个端点的脱敏差异 | /rest/memories 泄邮箱 vs /api/Feedbacks 脱敏(F-02 防护不一致) |
| **③流向:数据去哪?** | 搜索/评论/昵称→哪些渲染点(DOM/API/邮件);上传→存储路径可猜? | 反射点标记、存储后跨用户可见性、文件名可控 | /search?q 反射;上传文件名遍历 |

### 5.2 信号补充(API 特有)

- **错误分型**:500 带栈(Express/Sequelize)=信息泄露+注入候选;统一 error JSON=设计内
- **枚举响应差**:存在 vs 不存在的资源返回结构/文案差异(oracle)
- **鉴权不一致是最肥的面**:同数据多端点(Angular 常见 /api/X 与 /rest/X 并存)逐个比脱敏——juice-shop F-02 即此模式
- **PUT/PATCH/DELETE 语义**:改他人资源 id、删他人记录(BOLA-write);字段级 mass assignment
- **GraphQL**(如有):introspection 开关+resolver 越权

### 5.3 suspects 映射不变

接口型可疑点同样落 suspects.md(对象=端点+参数),映射 playbook 类(api-rest/arbitrary-x-authz/oauth-saml-jwt 等),确认弹药查表流程不变。


## 6. 因果链引用(20260831(轻量实现))

> 它家用运行时图数据库;我们用 **md 互链**达成同一目标:每个 confirmed 可回溯"从哪个疑问来、证据是哪几个、危害谁裁的"。

四级链(全部已存在于工序,只补显式引用):

| 级 | 载体 | 引用字段 |
|---|---|---|
| Evidence | evidence/ 原始包 | findings.evidence 列(已有) |
| Hypothesis | suspects.md S-xx | **findings 新增尾列 `src: S-xx`**(哪个语义疑问来) |
| Vulnerability | findings.md confirmed 行 | 主键 F-xx |

1. confirmed 行**必须**有 `src: S-xx`(除非来源是交接队列/用户指定——标注 `src: handoff`)

3. 散佚证据引用已有豁免分支(gate_check 查 3),不重复建


## 7. 理论发现排除清单(铁律:现象不是漏洞,漏洞是结果)

以下**不计入 findings、不进台账 confirmed、不写报告**——它们是"现象",不是"危害结果"。发现时一句话带过即可,浪费轮次深挖=预算漏洞:

| 排除项 | 为什么是现象 |
|---|---|
| CORS 宽松配置 | 需配合受害者访问恶意页才有危害;单独存在无结果 |
| SourceMap 泄露 | 只是源码可读,无直接危害结果(除非链出密钥→另立) |
| 安全头缺失(XFO/CSP/HSTS 等) | 需要具体攻击场景成立才升级;单独记 Info 都嫌多 |
| 内网 IP 泄露(响应/报错) | 路标不是门 |
| Stack Trace / 详细错误页 | 除非内嵌源码/数据流(F-11 级)或 SQL 异常实锤(F-14 级)——有链才留 |
| Cookie 无 HttpOnly(单独) | 须有 XSS 等"读 cookie 的手"才有意义;有手则随主洞定级 |
| 目录列表(无可敏感文件) | 空目录列表=现象 |

**判据一句话:没有完整可复现的 curl PoC 指向具体危害结果 = 不存在。**

> 注:上述项若与已 confirmed 主洞构成**升级链**的一部分(如 Stack Trace 内嵌 SQL 异常),随主洞定级,不单独立项——对照 01 §3.5.3 与 F-11/F-14 先例。
