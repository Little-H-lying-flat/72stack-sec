# 攻击面语义审计——发现的主引擎

> 视角:四战役产出溯源(20260831)的结论——**~90% findings 来自结构提取后的"表单/参数语义审视",payload 库直接命中≈0**。payload 是确认弹药,不是发现引擎;发现引擎是**对每个字段/防线/跳转的语义级提问**。本文件定义这道工序:Phase 4.5,在原型路由(10 号)之后、payload 探测之前。

---

## 1. 三问清单(对 Phase 3 采到的每个结构元素)

### 1.1 每个表单字段问:"服务端信吗?"

| 信号 | 语义可疑点 | 后续验证方向 |
|---|---|---|
| `type=hidden` 字段 | 客户端可控的敏感值(username/price/uid/redirect) | 篡改重发(5vshop F-11 Pay_cz username、F-24 total/allmoney/money1 同款) |
| 金额/数量/单价输入 | 服务端是否重算 | 改 0.01/负数/0(F-24 实证) |
| username/uid 出现在 body | 服务端从会话取还是从参数取 | 换他人用户名(F-11 跨用户建单) |
| id/pkid/pid 类参数 | 遍历越权 or intval | 换不存在值消费判别→换他人 id(BOLA) |
| verifycode/captcha 字段 | 服务端校验存在吗?session 码何时写入? | 空会话 trick(F-09 家族五口) |
| goto/redirect/url/return | 跳转白名单 | 换外域(注意:实测也可能不被消费,如 down.php) |
| 文件名/路径参数 | 服务端拼接? | 遍历序列(10-traversal-lfi) |
| **表单完整性**(隐藏 action/step 字段) | 缺字段时服务端行为? | 静默回显=mlecms act=register 实测陷阱 |

### 1.2 每个功能问:"这道防线真实存在吗?"

- **验证码**:字段存在≠校验存在(F-09 五口);session 码何时写入(图片请求/页面加载);失败提示是"不正确"还是"必填"(mlecms feedback 严 vs register 松——**同站可两套实现**)
- **审核门**:写入成功≠公开渲染(F-22 5vshop 有审核门 vs F-32 mlecms 无)——写入后必须回列表页看渲染
- **越权校验**:改 id/用户名/单号重发,看所有权校验(F-02/F-08)
- **失败锁定/限速**:同错误请求 5 连发看响应与延迟变化(F-17/F-25)
- **金额校验**:负数/0/非数字/超小额四发(F-34 对照)
- **回调验签**:无 sign POST 看是否静默丢弃(F-15)

### 1.3 每个跳转问:"这个跳转去哪?"

- `location=`/`Location:`/`meta refresh`/JS location 的目标来源(固定/参数化/base64)
- base64 形态先解码再判(mlecms recharge goto=L21sZWNt... 实测)
- 参数化跳转→外域测试;不被消费也记录(排除项亦是产出)

## 2. 产出物:语义可疑点清单(suspects.md)

Phase 4.5 输出写入 `work/<slug>/suspects.md`,每行:

```
S-01 | guestbook.php.title | 无验证码字段+列表页直出? | 表单提取 | 待验证 | → XSS 存储面
S-02 | Pay_cz.username | hidden 字段,服务端信? | 表单提取 | 待验证 | → 越权建单
```

列:**编号 | 对象 | 语义疑问 | 证据来源 | 验证状态(待验证/confirmed/clean) | 映射 playbook 类**。

**这份清单才是 payload 探测的输入**:每个 S-xx 按"映射 playbook 类"去查表拿确认弹药——弹药有了靶子,不再按类盲扫。

## 3. 覆盖指标(发现引擎的硬指标)

- **表单覆盖率 100%**:Phase 3 采到的每个表单 × 每个字段,三问 1.1 过一遍——漏一个字段=漏一个 S-xx 候选
- **认证后面 100%**:登录后可达的每个页面,表单+链接+参数全提取进三问——**全部 High 都来自这里**(F-02/08/14/24/32 实证),它不是"结构提取的一部分",是独立引擎
- **防线清单 100%**:1.2 的六种防线,每个认证后功能至少过一遍对应问句
- 未达标的"测完"=假测完(三查门闩追加第 4 查:**suspects.md 覆盖率**)

## 4. 与既有工序的关系

| 工序 | 分工变化 |
|---|---|
| Phase 3 结构提取 | 仍是入口(采结构),但产出直接喂 4.5 而非直接打 payload |
| **Phase 4.5 语义审计(本文件)** | **发现引擎**:结构→可疑点清单 |
| payload 探测(原 Phase 4) | **确认阶段**:只对 S-xx 清单按 playbook 查表确认 |
| 09 三查门闩 | 追加第 4 查:suspects 覆盖率 |
| 10 原型路由 | 仍决定"先打哪类";4.5 决定"有没有靶子" |
| playbook payload 库 | 降级为确认弹药库(反幻觉条款不变:用哪个 payload 仍须标出处) |
| 被动侦察(Phase 2) | 维持原样(用户指令:不降级) |
